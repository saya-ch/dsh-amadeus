## 0. 一句话定位

手机上的 Galgame——用户在手机上以剧场形式与“鲸鱼娘”人格的 Agent 互动，Agent 在电脑幕后真实执行工作，长文本以“小窗口”呈现。

## 0.5 实现快照（9/2 追实现）

> 本节是“产品今天长什么样”的现状总览，作为新人与后续讨论的快速入口。本节之前的 0~4 节是决策史（“为什么这样”），本节是现状（“现在是这样”）。

## 1. 叙事模型（已定稿）

### 1.1 关系定位：**A — 每场独立、性格固定**

- 每场会话是独立的"居家日常"，鲸鱼娘**性格固定、不记得上次聊了什么**。
- **不做**：好感度、跨会话记忆、关系成长弧线、episodic 剧情解锁。
- 体验重心压到 **"每一场会话本身的质量"**——单场够好，就成立。

### 1.2 单场结构：**C — 有开场、不做收尾**

- **有开场**：新建会话**必有一段鲸鱼娘的"登场"**（把用户拉进情境的第一步）。
- **不做收尾**：聊到用户离开就自然结束，不人为设计告别/小结落点。

### 1.3 开场白质地：**A — 稳定性优先（固定脚本）**

- 开场是**固定脚本**：画面转场 + 台词都预先设计好，**模型不参与开场**。
- 保证每次“鲸鱼娘登场”的质感稳定可控（不会开场说错话/平淡）。
- 接受“听多了会腻”的代价——稳定性优先于新鲜感。

> **9/2 落地确认**：开场由 **Host/preset 侧自动注入**（不走模型）——新建 amadeus 会话时，Host 自动注入一句开场白作为第一句 assistant 台词，用户进剧场即见鲸鱼娘已在说话。**当前尚未实现**（真实会话新建后无开场台词、直接等用户输入，preset 无开场指令），为已知缺口。开场白文案可做轮换池避免单调（轮换属增强，非本期必需）。

### 1.4 开场体量：**B — 轻量问候**

- 开场是**一句话**：新建会话 → 居家背景已就位 → 对话框弹出，一句鲸鱼娘问候（如“欢迎回来，今天想做什么？”）→ 进入等待输入。
- **不做**立绘入场/转场/多句开场戏——不抢戏、不拖沓，快速进入正题。
- 开场重复不设计为“仪式感”——轻量到不值得烦。

> **9/2 落地确认**：维持“轻量问候”体量（一句话），开场内容属 Host 侧维护（文案改在 Host/preset 配置文件，不必重打包 App）。

### 1.5 干活过程呈现：**文本进对话框，思考/工具调用进可展开小窗**

- **主角——文本输出**：Agent 的公开文本输出（`assistant/message`，含 `[[AMW:]]` 标签）直接在对话框里 Galgame 演出（打字机、立绘随标签变化）。
- **协议**：一个 `assistant/message` = 一段完整文本 + **一组标签**（段尾），标签决定整段 mood/sprite/voice/window；**不在 message 内拆分多标签**。一个 message = 一次展示（无翻页）。
- **配角——思考过程 + 工具调用**：**不翻译成鲸鱼娘台词**，而是收进一个**可展开的小窗**（用户想看才展开，如 DSH 的 thinking/tool 卡片折叠）。
- **不做**：把工具调用逐条翻译成“鲸鱼娘动作”播报、不接 `tool/call` 逐条演出（那是噪音）。
- **节奏原则**：文本是唯一的主角演出；思考/工具是“透明度”，需要时点开看，不需要时完全不打扰剧场。

> 注：这修正了早先“全程剧场化（鲸鱼娘独角戏）”的提法——演出聚焦公开文本，思考/工具不抢戏，作为可展开小窗存在。

#### 1.5.1 事件流向（已核对 DSH 事件词汇）

| 事件 | 去向 |
|---|---|
| `assistant/message` | 对话框 Galgame 演出（拆短句 + 标签驱动立绘） |
| `assistant/chunk` | 可选：长回复逐块打字（暂缓） |
| `user/message` | 用户的输入已在输入框，不额外演出 |
| `tool/call` / `tool/result` / `step/*` / `turn/*` / 思考类事件 | 可展开小窗（用户点开看） |

### 1.5.2 打字机节奏：由 agent 输出间隔自然驱动

- **打字机 = 标点停顿**（句内呼吸）：逗号/句号/省略号处有停顿，打字本身不机械。 **9/2 追实现：已实现（Typewriter）——逗号/顿号 +90ms、句号/叹号/问号 +135ms、省略号 +225ms、破折号 +90ms。**
- **不做人为句间停顿**：agent 每次输出文本块之间**本就有间隔**（生成/思考/工具调用），这段间隔足以让打字机展示完当前块——节奏是自然的，不需要额外设计。
- **接块规则**：下一块文本到达时，若上一块已展示完，直接展示这一块（不排队、不强制停顿）。

### 1.6 立绘：静态图像，切换时自然过渡

- **立绘是静态图像**：不做待机动效/说话动效/情绪幅度动画（呼吸缩放可以保留，但不做骨骼/摇摆/位移表达情绪）。
- **美术来源**：目前用现有素材；未来可用 GPT image2 扩充美术（新立绘/背景/差分），但**本期不依赖新素材**。
- **唯一要求**：切换 sprite/mood 时**自然过渡**（滑入/淡入，而非生硬切换）。
- **不做什么**：Live2D 接入（预留接口，未来再说）。

**9/2 追实现（重要：区分“表情差分”与“姿态/动作”）**：

- **女仆鲸鱼娘是唯一形象**：全部 9 张 sprite（`app/assets/sprites/`，git 跟踪的源素材）都是同一套深蓝女仆装人设的不同**姿态/动作**——不是两套画风。maid-left 与 whale-* 同为女仆装（maid-left 分辨率 1122×2019 更高，whale-* 统一 935×1683 系列）。实现上 sprite 映射到独立文件：shy→whale-shy、think→whale-confused、tool→whale-serious、wag→whale-cheerful、gray→whale-frightened、smile→whale-starry、talk→maid-left；whale-angry / whale-exasperated 两张已入库未映射。
- **表情差分 = 已定方向（9/2 用户决策）**：演出模型是 **动作 × 表情二维矩阵**——每个动作姿态都配一组表情差分，不只给标准站姿做（差分体量只是“做多少”的问题，按需/分批扩充）。产品要的差分 = 同一姿态/构图上换眉眼神情；动作承载“在干嘛”（talk 说话/tool 干活/wag 摇尾巴……），表情承载“什么情绪”（shy/think/happy/serious/confused/angry……）。**素材路线：以各动作现有图为参考，用 GPT image2 生成“同构图不同表情”差分**（image2 参考图保持形象一致性；表情集对齐 mood 枚举，每动作先做高频表情、按需扩充）。生成后仍是**整图替换**（每表情一张独立 png/webp），App 切换逻辑不变（文件命名约定如 `<action>-<emotion>.webp`），只是从“不同姿态”升级为“姿态 × 表情”可组合。**本期仍按现状整图替换运行，差分素材就位后替换。**

### 1.7 背景：静态，用户可选背景库

- **背景是静态图**：不做 Ken Burns 微动、不做时间/氛围滤镜（保持素材原样）。
- **背景库，用户可选**：内置多张背景（居家/工作/海边等），用户在设置里选择默认背景；未来用 GPT image2 扩充背景库。 **9/2 追实现：内置 3 张——居家书桌（默认）/ 海边学习 / 协作工坊（bg-claude / bg-deepseek / bg-gpt）；设置“演出”分页可选。**
- **过渡**：切换背景时自然过渡（Crossfade 保留）。

**9/2 追实现（方向决策：补“居家室内”场景）**：现有 3 张多为“工作/办公”场景（书桌/学习/工坊），缺真正“她在家里陪你”的居家室内背景，与 demo 相遇后“住在一起”的叙事不完全吻合。**定为用 GPT image2 生成居家室内背景**（客厅/卧室/窗边午后等，风格对齐现有深蓝金女仆装饰基调），扩充背景库后让“居家日常”叙事成立。**当前未做，属扩充方向；生成后加进设置背景库即可（切换逻辑不变）。**

### 1.8 对话框（galgame 门面）

- **名字牌**：独立的名字标签（对话框上方小牌子，带边框/底色，名字写在里面），不是对话框里一行字。**9/2 追实现：名字牌居中于对话框上方，带暖色底。**
- **对话框外观**：半透明深色、柔和渐变/描边，圆角——galgame 质感而非“聊天框”。**9/2 追实现：对话框上方叠蕾丝金线顶边（composer-frame 素材）、下方叠金纹章收边（bottom-crest 素材），深蓝/暖棕底 + 金描边——装饰往“华丽女仆宅”方向放大（用户选“装饰做大做显眼”方案）。**
- **▼ 提示**：呼吸箭头（轻微上下浮动，提示“有内容/等待中”）——不是翻页按钮（无翻页交互，见 1.5.2）。
- **点击反馈**：点对话框时“立即打满当前段”（打断打字机），带轻微按下反馈（缩放/变亮）。
- **用户输入体验（真实模式）**：输入框平时**隐藏**；对话框角落一个**按键**，点击展开输入框——**仅占一行空间**，展开时文本框依然正常显示文本（不挤占对话区域）。输入完自动收回，回到纯演出画面。

### 1.9 窗口系统（报告 / 预览 / 选项 / 历史）

- **长文本铁律（mode 层）**：**长内容不进对话框**——model 输出超长（>3 句/约 100 字）时：① system prompt 要求用 `save_report`/`show_preview` 存窗口，对话框只留 1~2 句鲸鱼娘口吻摘要；② Host 兜底：检测到超长文本时自动截断进对话框（保留前几句 + “…”），全文自动存成报告窗口。**长内容 = 工作交付物，不是对话**。
- **报告：专用页面 + 质感**。模型交的长文本不是“弹个查看器”，而是**鲸鱼娘递给你的一份东西**——有专属页面（卷轴/信件/卡片感），是演出的一部分而非工具弹窗。 **9/2 追实现：功能已通（报告窗口 = 标题“报告”+ 可滚动正文 + ✕，普通卡片）；“卷轴/信件专属质感”尚未做，用户确认仍要追（9/2）——报告值得做成“她递给你的一份东西”的质感（暖色信纸/卷轴边框/顶部纹章，与深蓝金装饰统一），与装饰放大同一方向、优先级待排。**
- **选项（ask_user_question）：对话框上方、立绘前方**。galgame 标准：选项浮在立绘前方/对话框上方，选了继续演出，不是底部弹窗。
- **预览**：保持功能（图片/代码/表格查看器），不做过多的戏。
- **历史（对话记录页）**：**透明底侧边栏**，**只显示文本记录**（即参加演出的对话，不含思考/工具），**上滑获取更早**——回忆感。

### 1.10 系统层

- **文字速度设置**：✅ 打字机快/慢可调（配合标点停顿）。
- **自动播放**：❌ 不做（等 agent 输出，自动播放无意义）。
- **demo 展示策略**：demo 仅**设备首次进 App 展示一次**（一个设备只展示一次，清除应用数据才重放）；之后可在设置里**重放**。
- **首屏逻辑（状态优先）**：
  - **有已保存网关** → 直接进**最后活动的 Amadeus 会话**（按 `updatedAt` 排序，不先选档）；切换会话有**单独按键**（进读档页）。
  - **没有网关** → 直接显示**连接页**（不进 demo）。
  - demo 是**设备首次的独立仪式**，与“是否有网关”无关。
- **无存档（读档页质感）**：**“档”的本质是 DSH 会话**——读档 = 选择一个 amadeus mode 会话；没有传统存档 UI。
  - **选档页是“读档页”质感**：每个会话像**一个存档位**（卡片带鲸鱼娘小表情/日期标签/工作区名），新建会话像**“开启新的一天”**——galgame 读档仪式感，而非任务列表。
  - **按工作区组织**：选档页按工作区**分组**，每个工作区内会话**倒序**（最后活动在前）；新建会话入口也在存档页，**样式需好好设计**（“开启新的一天”的仪式感）。
  - 保留**长按改名/删除**（轻量样式，不打断读档仪式）。
  - 创建会话：默认在**预设默认工作区**；也提供**文件选择器**让用户选工作区。
  - 会话只能是 amadeus mode（mode 隔离铁律）。
  - **切换会话入口**：剧场内单独按键进读档页（首屏直接进最新会话，不先选档）。
- **演出设置面板（合并齿轮 + 分页）**：✅ 剧场内一个齿轮入口，点进去**分页**——**演出**（文字速度/背景选择/BGM 选择音量/工具进度/demo 重放）+ **连接**（网关/配对/断开）；两类设置不混排。
- **后台/恢复策略**：任务期间退后台或杀进程——**进程存活** → 选择/完成时发**通知**；**进程被杀** → 下次进入按策略回到会话，获取历史 10 条事件，演出场景显示最新一条文本。
- **错误处理**：❌ Host 不额外处理——错误进事件流小窗（可见），对话框由模型全权决定是否/如何告知用户（靠模型自觉）。

### 1.11 沉浸层

- **环境音（sfx）**：❌ 本期删除（demo 和真实模式都不播放）；**预留接口**（未来可加，不删代码结构）。 **9/2 追实现：`res/raw/` 有 3 个静音占位 WAV（bgm_rain 雨声循环 / sfx_bell 铃 / sfx_wave 海浪），本地生成无授权依赖；配套 README 注明“用 CC0/开源素材替换同名文件即生效”（候选 freesound / pixabay / opengameart）；代码无播放器引用。**
- **背景音乐（BGM）**：✅ **用户可选 BGM 曲目**（如月夜/居家/温馨等），设置里可**关闭**、可**调音量**；未来用素材扩充曲库。 **9/2 追实现：确认按此做（用户决策）——找 CC0 雨声/居家 BGM 替换静音占位 + 接播放器（循环播放、设置选曲/调音量/关闭）。当前未做（prefs 已有 bgmTrack=rain 默认 / bgmEnabled / bgmVolume=70 字段与设置 UI）。**
- **语音（voice 标签）**：❌ 本期不播放、不做占位提示；**预留接口**（voice 标签继续作为元数据保留）。
- **触觉反馈**：✅ 只做**关键节点**——**发送消息时震动**（反馈“消息已送出”）；**不做**收到回复时震、不做逐字/逐句/普通点击震动（避免反感）。
  - 注：早先提的“完成任务/提出问题”节点**不做震动**（回复到达/选项出现不打断，靠演出本身提示）；震动仅保留“发送”这一个最自然的节点。
- **标题画面/logo**：✅ App 启动时“Amadeus: Whale”标题画面；**logo 由用户用 GPT image2 生成一个可爱的鲸鱼娘**。 **9/2 追实现：现状 logo = 🐳 emoji（96sp）+ 标题文字 + 副标题，淡入；用户确认仍等 GPT image2 生成专属 logo（期间不提前投入，不用手头素材做临时版）。**

### 1.12 demo 与真实模式的衔接：**配对 = 鲸鱼娘住进手机**

- **demo 是设备首次的独立仪式**：第一次进 App（无任何状态）→ 播 demo（相识：月夜初遇）→ 播完引导设置网关/配对 → 连接成功后鲸鱼娘“住进了手机”（把技术流程变成叙事节点）。
- **之后**（demo 已看过）：有网关直接进最新会话，没网关直接进连接页（不再播 demo）。
- **连接页本身是“连接剧场”**：背景 + 立绘 + 鲸鱼娘演出“等你接入”——配对过程 = 演出“她在等你连上”，配对成功 = 演出“她回来了”，然后进会话。
  - **首次配对引导**（demo 后）→ 配对成功 → **新建会话**（“她刚住进来”）。
  - **日常重连**（非 demo，没网关时）→ 配对成功 → **最后活动会话**（续聊）。
  - **9/2 追实现（实际落地方式）**：配对成功 → **有恢复的会话就进那个会话，否则进读档页**（用户自己选/新建）——**不自动新建会话**（用户确认维持此现状，见第十问 A）。首次配对后也是进读档页让用户自己开“新的一天”，避免自动建空会话；“她刚住进来”的叙事靠读档页“＋ 开启新的一天”按钮承接，不靠自动新建。
- **连接页与设置分离**：连接页（首屏仪式：立绘/演出/扫码）与设置里的“连接”分页（技术配置：地址/测试/配对）是**两套 UI**——首屏偏仪式，设置偏工具，不共用配对界面（逻辑层可共享，表现层分离）。
- 叙事上：相识（demo）→ 接入（配对）→ 居家日常（真实模式），弧线完整。

### 1.13 实施顺序：**B — 先出可玩的完整版，再精修**

- **第一阶段（完整版）**：用现有素材把整个流程走通——标题画面 → demo → 配对引导 → 选档页（读档质感）→ 剧场（对话框 galgame 化、输入唤出、选项浮层）→ 报告/预览/选项窗口。
- **第二阶段（精修）**：回头打磨演出细节（打字机标点、过渡、触觉、设置分页、BGM/背景库填充）。
- 素材（GPT image2 生成的背景/BGM/logo/立绘差分）就位后填充，不阻塞第一阶段。

**9/2 追实现：第一阶段已基本完成**（标题 → demo → 配对 → 读档页 → 剧场四窗口全通）；第二阶段进行中——已做：设置分页/主题切换/背景库/装饰放大；未做：打字机标点精细、过渡 spec、触觉打磨、BGM、logo。素材侧改用社区 maid-atelier 装饰（非 GPT image2），见 0.5/1.14。

### 1.14 视觉基调：**A — 暖色治愈（默认）+ 用户可选配色**

- **暖色治愈**：米白/暖棕/淡粉的底色，圆润卡片，柔和光感——“居家日常”的温馨感（贴合“鲸鱼娘在家陪你”的叙事）。
- **配色用户可选**：设置里可切换**配色主题**（暖色治愈为默认，另提供其他主题如深色/冷调等）；未来可扩充主题。 **9/2 追实现：两套——暖色治愈（默认）/ 深色，设置“演出”分页 ThemeChip 切换。**
- **主题系统 = A+B 混合**：Compose Material3 主题打底（标准组件跟随）+ 自定义语义色扩展（galgame 专属件——名字牌/对话框/读档卡片等用自定义色板）。
- 所有 UI 组件（对话框/读档页/设置/窗口/连接页）的配色跟随所选主题。

**9/2 追实现（重要演化）：装饰语言从“暖萌”走向“深蓝 × 金 × 女仆蕾丝”华丽线。**

- 背景基调仍跟随用户所选主题（暖/深），但**跨主题叠加一层 maid-atelier 装饰素材**（金线蕾丝、深海蓝横幅、金卷草纹章、缎带、盾牌），形成“女仆华丽宅”的视觉语言——**装饰是主题之上的独立层，不随主题切换**。
- 装饰密度选择：用户在“暖色治愈 / 深色 × 装饰小 / 装饰大”等选项中选过 **C（装饰做大做显眼）**——金线包边、横幅等做显眼，读档/设置/对话框全面铺开（见 0.5 节表格）。
- 素材合规：装饰素材来自 DSH 社区（CC BY-NC-SA 4.0，见 assets/SOURCES.md），**产品层面接受“社区素材驱动视觉风格”**——视觉基调不再纯由主题色决定，而是由可用素材的气质决定（素材换了，风格跟着走）。

### 1.15 过渡语言：**统一动画 spec**

- **定义一套统一的“鲸鱼娘过渡语言”**：所有界面出现/消失用同一套动画语法，用户形成“手感记忆”。
- **覆盖层**（窗口/小窗/设置）：统一“从边缘滑入 + 淡入”。 **9/2 追实现：覆盖层滑入未实现（设置面板直接浮起）；跨屏切换（连接→读档→剧场）为直接换屏。**
- **内容切换**（立绘/背景/对话）：统一“短 Crossfade + 轻微缩放”。 **9/2 追实现：立绘/背景用 Crossfade；呼吸▼/打字机动画在；统一时长与缩放 spec 未建。**
- **统一时长**：覆盖层约 250ms、内容切换约 300ms。
- 代码上是**一组可复用的动画 spec**，实施时各组件引用同一套。 **9/2 追实现：动画 spec 尚未抽成独立模块，散在 DialogueBox/TheatreStage 内。**

## 2. 由上述决策推出的边界（减少摇摆）

| 领域 | 结论 | 因为 |
|---|---|---|
| 好感度 / 关系系统 | ❌ 不做 | 叙事模型 A |
| 跨会话记忆 | ❌ 不做 | 叙事模型 A |
| 开场设计 | ✅ 必做（固定脚本、轻量） | 单场结构 C + 开场质地 A + 体量 B |
| 收尾 / 告别系统 | ❌ 不做 | 单场结构 C |
| 会话内戏剧弧线 | ✅ 自然产生（靠模型人格） | 每场独立 + 无强制框架 |
| 干活过程呈现 | ✅ 文本→对话框，思考/工具→可展开小窗 | 主角/配角分离，避免噪音 |
| 工具逐条播报 | ❌ 不做 | 改为可展开小窗 |
